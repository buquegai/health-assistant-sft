## 结果摘要

首版 Vue 3 + TypeScript（前端框架与类型语言）和 FastAPI + SQLite（后端框架与数据库）应用已完成，聊天页支持模型选择并按会话保存。前端生产构建、依赖审计、后端自动化测试、模型选择器双模型模拟测试和真实浏览器聊天流程通过。A13 健康内容抽查不通过；当前版本只适合受控的低风险界面演示，不可用于诊断、用药剂量建议或急救分流。应用没有可靠的高风险输入拦截或答案安全过滤，不应对外开放或进行真实用户试运行。

## 模型依赖与运行

使用推理配置 `configs/psychology_infer.yaml`：基础模型 `Qwen3-1.7B`，LoRA（低秩适配器）目录 `/home/woei/experiments/health-sft/train_01`，4-bit `bnb` 量化。服务通过 `webapp/serve_model.py` 适配停止语义，LLaMA-Factory 与模型权重继续使用现有 WSL 环境。

当前部署注册表 `webapp/backend/model_registry.yaml` 配置两个选项：`health-assistant`（健康助手微调版）和 `qwen3-base`（Qwen3-1.7B 原始模型）。两者共用模型服务，分别启用、关闭未合并的 LoRA。聊天顶部选择器会显示后端授权模型；新建会话使用当前选择，已有会话切换后保存其 `model_id`（模型 ID），刷新后恢复选择。已有问答历史会继续作为所选模型的上下文。添加其他微调模型时，仍需配置对应服务及模型名；本次没有自动部署 `train_swanlab_01`（第二次训练版本）。

依照 `README.md` 中的三终端步骤分别启动模型服务、应用后端和前端。前端地址为 `http://localhost:5173`；后端监听 `127.0.0.1:8080`，模型 API（接口）监听 `127.0.0.1:8000`。首次启动需安装后端 Python 依赖和前端 npm 依赖；运行环境需有既存的模型权重、LoRA、CUDA 与 Qwen3 tokenizer 文件。

## 2026-11-06 原始模型切换验收
