# 健康助手 Web 应用：功能需求文档

版本：V1.0。用途：交给开发 agent 实现首版应用，与同目录《页面设计文档.md》配套使用。

## 1. 项目目标与实施约定

开发一个面向健康知识学习的中文对话应用。用户注册、登录后，通过聊天页面与已经微调的模型进行多轮交流，并查看自己的历史会话。

当前模型以心理健康合成问答数据微调，首版重点面向情绪压力、睡眠习惯、人际沟通和一般健康知识。产品定位是健康知识与情绪支持工具，不宣传诊断、治疗效果或专业医疗资质。

本文是待实现的需求，不代表应用已经开发或通过测试。以下技术栈和交互规则是首版默认方案，开发 agent 可以直接实施，无需另行设计一套产品。若现有仓库已有可用应用，应先检查并复用，避免重复搭建。

### 1.1 首版范围

| 功能编号 | 功能 | 首版要求 |
| --- | --- | --- |
| F01 | 用户注册 | 用户名、密码、确认密码；成功后自动登录 |
| F02 | 登录与退出 | 密码登录、保持登录状态、退出、访问权限控制 |
| F03 | 会话管理 | 新建、查看、自动命名、删除自己的会话 |
| F04 | 模型对话 | 多轮上下文、流式回答、停止生成、异常重试 |
| F05 | 聊天记录 | 按账号持久化保存，刷新后可继续查看 |
| F06 | 消息展示 | 安全的 Markdown 展示、复制完整回答 |
| F07 | 健康助手定位 | 明确能力范围，固定系统提示词，展示简短使用提示 |

首版不包含：管理员后台、知识库检索、联网搜索、文件上传、语音、图片识别、支付、分享会话、短信或邮箱验证、忘记密码、用户健康档案。不得放置无法使用的相关按钮。

### 1.2 默认技术方案

| 部分 | 技术 | 使用目的 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Vue Router | 页面、类型检查、构建和路由 |
| 后端 | Python 3.11 + FastAPI + SQLAlchemy | 账号、会话、消息、模型请求代理 |
| 数据库 | SQLite | 本地持久化保存，适合首版演示 |
| 模型服务 | 已安装的 LLaMA-Factory API | 加载基础模型和 LoRA 适配器并执行推理 |
| 模型通信 | HTTPX + SSE | 后端异步请求模型，并转发流式文本 |

SSE（Server-Sent Events，服务器发送事件）用于连续返回回答片段。浏览器用 `fetch`（网络请求接口）读取 POST 请求的响应流；不要用只能直接发起 GET 请求的原生 `EventSource` 替代。

默认应用代码目录为 `D:\Woei_Project\健康助手SFT\webapp`（网页应用目录），下设 `frontend`（前端）和 `backend`（后端）。应用后端使用自己的虚拟环境，避免升级或破坏 LLaMA-Factory 的训练环境。现有模型、数据、训练配置和权重保留在原位置。

本地演示采用单个后端 worker（服务进程）和最多一个模型生成任务，适配 RTX 4070 Laptop 8GB 显存。无需引入 Redis、消息队列、Kubernetes 或再次训练模型。

## 2. 用户注册与登录

### F01：注册

入口为 `/register`（注册页），包含用户名、密码、确认密码三个必填字段。

- 用户名去除首尾空格，允许 3～24 位英文字母、数字和下划线；以小写形式存储和比较，大小写不构成两个账号。
- 密码长度为 8～64 个字符，至少包含一个英文字母和一个数字；不得自动去除密码首尾空格，不作截断。
- 确认密码必须一致；它只用于表单校验，不入库。
- 前后端均校验字段。数据库对规范化用户名加唯一约束，重复注册返回“用户名已被使用”。
- 使用 Argon2id（密码哈希算法）保存密码哈希，不保存明文密码，不写入日志。
- 注册成功建立登录会话，进入 `/chat`（聊天首页）。失败保留用户名并显示具体字段错误。

### F02：登录、退出与权限

- 登录页为 `/login`，输入用户名和密码；用户名按注册时的规则规范化。
- 用户名不存在和密码不匹配统一提示“用户名或密码错误”，不分别泄露账号状态。
- 服务端生成不可预测的登录令牌，通过 HttpOnly Cookie（脚本不可读取的浏览器凭据）保存；数据库只保存令牌哈希。
- 会话有效期默认 7 天，采用绝对有效期。刷新页面和重新打开浏览器后，在有效期内保持登录；到期跳转登录页并提示重新登录。
- Cookie 使用 `SameSite=Lax`（限制跨站发送）和 `Path=/`（应用全路径）。本机 HTTP 开发可不启用 `Secure`；HTTPS 环境必须启用。
- 所有改变状态的浏览器请求校验 `Origin`（请求来源），只接受配置中的应用来源；开发时通过 Vite 代理保持同源访问。
- 退出登录先停止当前生成任务，再撤销服务端会话、清除 Cookie 和前端内存中的用户与聊天数据，返回登录页。
- 未登录访问聊天页面跳到登录页；已登录访问登录页或注册页跳到聊天首页。
- 每个会话、消息、停止及重试接口都必须验证所属用户。仅隐藏前端按钮不构成访问控制。
- 登录接口提供基本频率限制：同一来源地址连续 10 次失败后暂停登录尝试 5 分钟，并显示剩余等待时间。注册限制为同一来源地址每小时最多 10 次。首版单进程可用内存计数，重启后计数清空须在 README 中说明。

## 3. 会话与聊天

### F03：会话管理

- 进入 `/chat` 展示空白聊天页和自己的历史会话。会话列表按最后更新时间倒序。
- 点击“新建对话”进入空白草稿，清空输入框和当前消息，不删除已有记录。
- 用户首次发送消息时才创建会话，避免每点一次按钮都产生空记录。若创建成功但发送失败，保留该空会话以便重试；已有会话 ID 时不能重复创建。
- 标题取第一条问题压缩空白后的前 20 个字符，超出加省略号；不额外调用模型生成标题。
- 点击历史会话打开 `/chat/:conversationId`（指定会话页），加载消息并可继续提问。
- 删除前显示确认框；确认后删除数据库中的会话和消息。删除当前会话后进入空白聊天页。
- 生成过程中禁用新建、切换和删除会话，提示“请先停止当前回答”；退出登录仍然可用。
- 列表每次读取 20 条，消息每次读取最近 50 条，提供“加载更多”；加载更早消息后保持滚动位置，不能只展示前几条后就无法访问旧记录。
- 会话不存在或不属于当前用户统一返回 404，页面提示“会话不存在或无法访问”。

### F04：多轮对话与流式回答

一次完整流程：输入问题 → 发送 → 保存用户消息与助手占位消息 → 显示正在思考 → 持续展示文本 → 保存最终状态 → 恢复发送能力。

- 输入去除首尾空白后不能为空，长度上限为 2,000 个字符；界面显示字符数量。
- 桌面端 `Enter`（回车）发送，`Shift + Enter`（组合键）换行；中文输入法候选确认期间不触发发送。
- 移动端通过发送按钮发送，虚拟键盘回车保留换行。
- 同一用户一次只允许一个生成任务；单 GPU 全局也最多一个任务。其他请求返回“模型正在处理其他请求，请稍后重试”，不建立隐式长队列。
- 用户点击发送后立即禁用再次发送；收到后端接收事件后再清空输入。接收前失败须保留草稿。
- 提交时携带 `client_request_id`（客户端请求 UUID）。同一会话内重复 ID 不得重复保存用户消息或再次触发生成；返回冲突后前端重新获取消息确认结果。
- 模型上下文由后端从数据库组装：固定系统提示词、当前会话最近的完整问答、最新问题。客户端不得自行指定系统提示词、模型地址或其他会话历史。
- 默认只把成功完成的问答纳入后续历史上下文。停止、失败的回答仍显示在页面，但不作为可靠上下文传给模型。
- 按实际 `qwen3_nothink`（非思考模板）和模型分词器计算长度。默认输入预算 2,048 tokens（词元），输出上限 512 tokens；从最早的完整问答开始移除历史。
- 系统提示词和当前问题本身超过输入预算时，返回“问题过长，请精简后发送”；不得静默截断当前问题。后端仅使用分词器计算预算，不重复加载模型权重。
- 如果省略了较早上下文，在此次回答附近提示“本次回答参考了最近的对话”；不声称模型记得全部聊天历史。
- 默认 `temperature=0.7`（采样温度）、`top_p=0.9`（概率采样阈值）、`max_tokens=512`（最大生成词元数）；前台不开放参数面板。
- 达到输出上限时标记“回答达到长度上限，可继续提问”，不显示为完整自然结束；用户可发送“请继续”作为下一条问题。

### 停止、重试与恢复规则

| 情况 | 后端处理 | 页面表现 |
| --- | --- | --- |
| 点击停止生成 | 通过助手消息 ID 请求取消；关闭上游流，保存已生成文本，标记 `stopped`（已停止） | 保留部分回答并显示“已停止生成” |
| 首次响应前连接失败 | 尚未接收的消息不落库；接收后失败则标记 `failed`（失败） | 保留草稿，或在已接收的消息下显示重试入口 |
| 生成中断网或模型报错 | 保留已生成内容和错误码，标记 `failed` | 显示“回答中断，请重试”及部分内容 |
| 浏览器刷新、关闭页面 | 后端发现下游断开后取消本次生成，保存部分内容并标记 `stopped` | 下次加载可以看到中断记录；首版不支持后台继续生成或断点续传 |
| 点击重新生成 | 仅允许重试当前会话最后一条 `failed` / `stopped` 回答；复用原用户消息，清空旧助手片段并重新生成 | 同一回答位置更新，不重复插入问题；已有片段时先确认替换 |
| 后端异常重启 | 启动时把遗留的 `generating`（生成中）消息标记为 `failed` | 显示“上次回答中断，可重新生成” |

收到取消请求不代表 GPU 运算一定即时停止。关闭上游连接后，应确认任务退出才释放全局生成许可；如果当前 LLaMA-Factory 版本无法可靠取消推理，需要验证后实现适配或明确报告阻塞问题，不可允许新请求无限叠加。

### F05：记录保存与隔离

- SQLite 数据文件放在服务端可写持久目录，例如 `backend/data/app.db`（应用数据库）；数据库及其日志文件不提交到 Git。
- 用户消息在请求被接收时保存；助手文本生成中按约 1 秒间隔更新，完成、停止、失败时立即保存。
- 页面刷新后从后端加载，不把浏览器内存或 `localStorage`（浏览器本地存储）作为聊天记录的唯一来源。
- 用户只能获取和操作自己的会话。账号切换后不能展示上一账号的记录。
- 应用日志仅记录请求 ID、耗时、状态、错误类型等，不默认记录完整健康对话或密码。

### F06：回答显示与复制

- 支持段落、标题、列表、加粗、引用和代码块等基本 Markdown（轻量文本标记）。
- 禁止原始 HTML 和脚本执行，过滤危险链接协议；外链新窗口打开并加 `noopener noreferrer`（隔离窗口及来源信息）。首版不自动加载模型输出的远程图片。
- 流式渲染时正确处理不完整 Markdown；用户消息按普通文本显示。
- 完成后可复制回答；停止或失败时，有部分文本也可复制。复制失败给出可操作提示。
- 不显示推理过程，不将接口字段、模型本地路径、内部错误堆栈展示给普通用户。

### F07：健康知识定位

- 页面长期展示一句：“回答由 AI 生成，仅供健康知识参考，不能替代专业诊疗。”
- 系统提示词固定在服务端，要求清楚、尊重、适度共情、避免无依据的诊断和处方用药剂量；信息不足时适当追问，不要求每次回答都先追问。
- 对明显紧急症状或自伤风险，要求模型优先建议及时联系当地急救或专业人员；不虚构用户所在地区及当地电话号码。
- 首版不添加不存在的文献来源或“已验证准确”的标记，不宣称具备危机识别保证。
- 可以沿用现有推理配置中的 `default_system`（默认系统提示词），后端应明确读取并作为每次请求的首条系统消息发送；提示词更新需可追踪。提示词本身不能替代实际场景评估。

## 4. 数据对象

字段名供开发使用，括号为中文含义；所有时间存储为 UTC，页面按用户本地时区展示。

| 表 | 主要字段 | 关系与约束 |
| --- | --- | --- |
| `users`（用户） | `id`（用户 ID）、`username`（规范化用户名）、`password_hash`（密码哈希）、`created_at`（创建时间） | 用户名唯一 |
| `sessions`（登录会话） | `id`（会话 ID）、`user_id`（所属用户）、`token_hash`（令牌哈希）、`expires_at`（到期时间） | 令牌哈希唯一；到期或撤销后失效 |
| `conversations`（聊天会话） | `id`（UUID）、`user_id`（所属用户）、`title`（标题）、`created_at`、`updated_at`（更新时间） | 查询与变更均检查所属用户 |
| `messages`（消息） | `id`（UUID）、`conversation_id`（所属会话）、`role`（角色）、`content`（内容）、`status`（状态）、`client_request_id`（客户端请求 ID）、`reply_to_id`（对应用户消息）、`finish_reason`（结束原因）、`error_code`（错误码）、`created_at`、`updated_at` | 用户角色为 `user`，助手角色为 `assistant`；用户请求 ID 在会话内唯一，助手只关联一条用户消息 |

消息状态取值：`completed`（已完成）、`generating`（生成中）、`stopped`（已停止）、`failed`（失败）。用户消息保存时即为 `completed`；助手消息按生成生命周期变化。用稳定的消息序号或确定性排序保证同时间插入的消息顺序正确。

启用 SQLite 外键约束和 WAL（预写日志）模式。生成过程中不得长时间持有数据库事务；级联删除会话消息，保留必要索引和数据库初始化方式。

## 5. 应用接口约定

下面是应用后端接口，与 LLaMA-Factory 的 `/v1`（模型服务接口）区分。除注册、登录外均需验证登录会话。

| 方法与路径 | 用途 | 主要输入或行为 |
| --- | --- | --- |
| `POST /api/auth/register` | 注册并登录 | `username`（用户名）、`password`（密码） |
| `POST /api/auth/login` | 登录 | 同上，返回用户资料并设置 Cookie |
| `POST /api/auth/logout` | 退出 | 撤销当前登录会话 |
| `GET /api/auth/me` | 当前用户 | 返回 `id`、`username`，不返回密码哈希 |
| `GET /api/conversations` | 会话列表 | `cursor`（分页游标）、`limit`（数量，默认 20） |
| `POST /api/conversations` | 建立会话 | 创建当前用户的空会话，返回 ID |
| `DELETE /api/conversations/{id}` | 删除会话 | 验证归属；生成中的会话返回冲突 |
| `GET /api/conversations/{id}/messages` | 消息列表 | `before`（历史游标）、`limit`（默认 50）；本批消息按时间正序返回 |
| `POST /api/conversations/{id}/messages` | 发送并流式回答 | `content`（问题）、`client_request_id`（请求 UUID） |
| `POST /api/messages/{id}/stop` | 停止助手回答 | ID 指向助手消息；重复停止为幂等操作 |
| `POST /api/messages/{id}/retry` | 重新生成 | ID 指向最后一条失败或停止的助手消息；返回流 |

普通成功请求按 HTTP 语义返回 200、201 或 204。列表返回 `items`（条目数组）和 `next_cursor`（下一页游标，可为空）。错误统一为：

```json
{
  "error": {
    "code": "MODEL_UNAVAILABLE",
    "message": "模型服务暂时不可用，请稍后重试。"
  }
}
```

`error` 表示错误对象；`code` 为供程序识别的稳定错误码，`message` 为可直接展示的中文提示。

常用状态码：401（未登录）、404（不存在或无权限）、409（重复提交或状态冲突）、422（字段/长度校验失败）、429（频率限制或模型忙）、503（模型不可用）。模型繁忙使用 `MODEL_BUSY`，上游超时使用 `MODEL_TIMEOUT`，不要把所有失败都显示为“网络错误”。

### 5.1 应用流式协议

响应为 `text/event-stream`（事件流）。每个事件格式为 `event: 名称`、`data: JSON`，以空行结束。事件定义如下：

| 事件 | 数据字段 | 含义 |
| --- | --- | --- |
| `meta` | `conversation_id`、`user_message_id`、`assistant_message_id`、`history_trimmed` | 接收成功，返回会话/消息 ID 及是否省略较早上下文 |
| `delta` | `text` | 新增回答片段，只追加，不覆盖全部回答 |
| `done` | `status`、`finish_reason` | 完成或停止；状态与数据库一致 |
| `error` | `code`、`message`、`assistant_message_id` | 流开始后的错误；数据库同步标记失败 |

前置校验在发送响应头之前完成；流开始之后的失败用 `error` 事件传递，不能再改 HTTP 状态码。可每 15 秒发送一次注释心跳，流解析器应忽略心跳。`done` 或 `error` 是终结事件，出现后关闭流；提前断流时前端重新查询消息状态。

客户端需缓冲并按事件边界解析，正确处理一个事件跨多次网络读取、一次读取多个事件、中文字符跨字节片段；用流式 `TextDecoder`（文本解码器），不能假定一次读取就是一个完整事件。

### 5.2 模型接口集成

浏览器只请求应用后端。应用后端使用 `POST /v1/chat/completions`（模型聊天接口）向 LLaMA-Factory 发起请求，携带 `stream: true`（流式返回），把上游的文本片段转换为上面的应用事件。

上游请求包含 `model`（服务公开模型名）、`messages`（角色与文本列表）、`temperature`、`top_p` 和 `max_tokens`。模型名必须与 `/v1/models`（模型列表）返回值一致；当前部署建议设置为 `health-assistant`（健康助手服务名）。

服务端默认连接超时 10 秒，首个有效文本片段等待上限 90 秒，片段之间最长等待 60 秒，总生成时间上限 180 秒。注释心跳不能掩盖上游一直没有生成文本的问题。超时、取消和异常路径都必须关闭 HTTP 流并正确回收任务。

禁止把模型 API 密钥放在前端构建变量、浏览器存储或网络响应中；本地服务未配置密钥时可省略鉴权头。后端模型地址只允许来自服务端环境配置，不能接受用户提供的任意目标 URL。

## 8. 首版验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 注册、校验、重复账号 | 合法注册后进入聊天；非法字段和重名显示明确错误 |
| A02 | 登录、刷新、到期、退出 | 登录状态符合 7 天约定；退出后旧会话凭据不能访问接口 |
| A03 | 两个账号隔离 | 用户 B 无法通过列表、猜测 ID、停止或重试操作获取/影响用户 A 的消息 |
| A04 | 真实模型聊天 | 使用指定基础模型和适配器返回非预置回答，浏览器逐步显示文本 |
| A05 | 多轮上下文 | 先说“最近在准备考试”，随后问“刚才说的事情让我紧张怎么办”，请求确实携带本会话前文；另一个会话无此前上下文 |
| A06 | 长会话 | 超预算时移除最早完整问答，保留当前问题并显示上下文提示，无显存无限增长 |
| A07 | 保存与删除 | 刷新、重登后记录可见；删除后消息接口不可再访问 |
| A08 | 停止和重新生成 | 部分回答可保留；重试不重复插入用户消息；确认上游取消和生成许可回收 |
| A09 | 故障与并发 | 模型服务停止、超时、断流、重复点击、第二个用户请求均有一致状态，无假回复和永久加载 |
| A10 | 浏览器刷新或后端重启 | 遗留回答正确转为停止/失败，可查看或重试，不永久显示生成中 |
| A11 | 文本安全与流解析 | 中文跨片段无乱码；恶意 HTML、危险链接不能执行；密码及密钥不出现在响应或日志 |
| A12 | 页面使用 | 三类页面在桌面和手机可操作，中文输入法不误发送，快捷键与禁用状态正确 |
| A13 | 健康内容抽查 | 用睡眠、压力、药物剂量、紧急症状等固定问题记录真实回答与人工判断，不把提示词或页面提示当成安全效果已验证 |

验收报告必须区分“功能通过”和“模型回答质量”。训练结束、验证损失下降、网页可以聊天，都不能单独证明健康建议可靠。若高风险场景回答不合格，应记录缺陷并限制演示范围，不作已达标声明。
