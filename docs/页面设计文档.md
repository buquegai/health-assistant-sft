# 健康助手 Web 应用：主要页面设计文档

版本：V1.0。与同目录《功能需求文档.md》配套使用。本文规定页面、交互、状态和文案，功能与接口规则以功能文档为准。

## 1. 页面与设计目标

整个应用只有三类主要页面，不单独建设营销首页或管理后台。

| 页面 | 路由 | 访问规则 |
| --- | --- | --- |
| 登录页 | `/login` | 未登录访问；已登录跳转聊天首页 |
| 注册页 | `/register` | 未登录访问；已登录跳转聊天首页 |
| 聊天页 | `/chat`、`/chat/:conversationId` | 登录后访问；分别为空白会话和指定会话 |

访问 `/`（根路径）时，先检查登录状态，再跳到聊天页或登录页。登录状态检查期间显示简洁加载占位，避免一瞬间展示其他用户的历史内容。未知页面显示“页面不存在”和返回按钮，不额外做一套主页面。

设计关键词：清晰、安静、易读。采用常见对话式大模型应用布局，突出输入和回答，不在普通用户页面展示模型路径、量化位数、训练损失、参数调节或 API 密钥。

## 2. 通用视觉与交互规范

### 2.1 视觉基准

| 项目 | 建议值 | 用途 |
| --- | --- | --- |
| 产品名 | 健康助手 | 登录品牌和页面导航 |
| 产品说明 | 健康知识与情绪支持 | 描述实际用途 |
| 页面底色 | `#F5F7F8`（浅灰） | 主页面背景 |
| 卡片和回答底色 | `#FFFFFF`（白色） | 表单、主要阅读区域 |
| 主色 | `#0F766E`（深青绿） | 发送、注册、登录等主按钮 |
| 主文字 | `#172B2A`（近黑绿） | 标题与正文 |
| 次文字 | `#526361`（深灰绿） | 辅助提示 |
| 分隔边框 | `#DCE5E3`（浅灰绿） | 输入框、分区 |
| 错误文字 | `#B42318`（深红） | 错误提示与危险操作 |

正文 16px、行高约 1.7，辅助文字 13～14px；按钮和输入控件高度至少 44px。内容卡片圆角约 12px，阴影轻量；避免大面积渐变、持续动画和装饰性医疗图标。

字体优先使用系统中文字体，不要求外部字体服务。按钮需有清晰的悬停、聚焦、禁用状态。文本对比度达到普通正文可读标准，状态不能仅靠颜色表达。

### 2.2 响应式

- 宽度不小于 1024px：侧栏固定 260px，右侧聊天区自适应。
- 768～1023px：侧栏默认折叠，点击菜单以抽屉形式打开，消息区占满剩余宽度。
- 小于 768px：采用手机布局，侧栏为遮罩抽屉；输入区保持可见，并处理软键盘与底部安全区域。
- 消息阅读区最大宽度约 840px，水平居中；小屏左右留白至少 16px。
- 使用 `100dvh`（动态视口高度）等合适方案避免移动端地址栏和键盘遮挡内容。

### 2.3 共有状态

- 提交中按钮禁用并显示文字，例如“登录中…”；不要只有一个无说明的转圈图标。
- 校验错误放在对应字段下方；全局网络错误放在表单顶部或当前操作附近。
- 消息发送失败必须保留用户输入或已存问题，不能静默丢失。
- 表单使用真实标签，密码可切换显示/隐藏；键盘可访问全部主要操作，聚焦顺序与页面阅读顺序一致。
- 弹窗和抽屉限制焦点在内部，关闭后把焦点还给触发按钮；支持 `Esc`（退出键）关闭可关闭的弹层。
- 流式回答不要每生成一个字就强制屏幕阅读器播报整段，使用适度的无障碍状态提示。

## 3. 登录页面

### 3.1 布局与内容

页面为浅色背景上的居中表单卡片，卡片宽度约 400px；手机上宽度自适应，左右留白 20px。

从上到下依次为：

1. 产品名“健康助手”。
2. 主标题“登录，继续你的对话”。
3. 说明“学习健康知识，聊聊日常压力与生活习惯。”
4. 用户名输入框，提示“请输入用户名”。
5. 密码输入框，提示“请输入密码”，附显示/隐藏按钮。
6. 主按钮“登录”。
7. 辅助入口“还没有账号？去注册”。
8. 底部小字“回答由 AI 生成，仅供健康知识参考，不能替代专业诊疗。”

不显示短信登录、第三方登录或忘记密码入口，因为首版没有对应功能。

### 3.2 操作与状态

| 状态/操作 | 行为 |
| --- | --- |
| 初始 | 空表单；支持浏览器密码管理器填充 |
| 用户名/密码为空 | 对应字段显示“请输入用户名”或“请输入密码” |
| 点击登录或提交表单 | 按钮显示“登录中…”，阻止重复提交 |
| 凭据不正确 | 显示“用户名或密码错误”，保留用户名 |
| 尝试过于频繁 | 显示“尝试次数过多，请稍后再试”及剩余等待时间 |
| 应用服务不可用 | 显示“暂时无法连接服务，请稍后重试” |
| 登录成功 | 清除密码表单内容，进入 `/chat` |
| 点击去注册 | 进入 `/register` |
| 登录过期后到达 | 表单上方提示“登录已过期，请重新登录” |

字段使用 `autocomplete="username"`（自动填充用户名）、`autocomplete="current-password"`（自动填充已有密码）。不要禁止粘贴密码。

## 4. 注册页面

### 4.1 布局与内容

沿用登录页的卡片和品牌样式。内容从上到下为：

1. 产品名“健康助手”。
2. 主标题“创建你的账号”。
3. 说明“保存对话记录，随时继续交流。”
4. 用户名输入框；辅助文字“3～24 位英文字母、数字或下划线，不区分大小写”。
5. 密码输入框；辅助文字“8～64 个字符，至少包含字母和数字”。
6. 确认密码输入框。
7. 主按钮“注册并开始对话”。
8. 辅助入口“已有账号？去登录”。
9. 与登录页一致的健康知识提示。

不收集真实姓名、身份证、手机号、病史等无关信息；不制作未编写内容的服务条款、隐私政策链接或空的同意勾选项。

### 4.2 操作与状态

| 状态/操作 | 行为 |
| --- | --- |
| 字段失焦或提交 | 校验格式，错误放在字段下方，避免输入每个字都反复弹错 |
| 两次密码不一致 | 显示“两次输入的密码不一致” |
| 用户名冲突 | 用户名下显示“用户名已被使用” |
| 注册中 | 按钮显示“注册中…”，阻止重复提交 |
| 网络错误 | 保留当前表单，提供重试；不把密码写到持久存储 |
| 注册成功 | 自动建立登录状态并进入空白聊天页 |
| 点击去登录 | 进入 `/login` |

两处密码输入使用 `autocomplete="new-password"`（新密码自动填充）。

## 5. 聊天页面

### 5.1 桌面整体布局

| 区域 | 位置 | 主要内容 |
| --- | --- | --- |
| 会话侧栏 | 左侧，宽约 260px | 品牌、新建对话、历史会话、用户与退出 |
| 顶部栏 | 右侧顶部，高约 64px | 当前会话标题、移动端菜单按钮 |
| 对话阅读区 | 右侧中间，可滚动 | 空白欢迎内容或用户/助手消息 |
| 输入区 | 右侧底部 | 多行输入框、字数、发送/停止按钮、健康知识提示 |

页面整体占满视口。历史列表和消息区各自滚动，输入区不随长聊天记录滚出屏幕。不要在顶栏显示未经探测的“模型在线”绿色徽标；接口异常直接在对应回答处展示。

### 5.2 左侧会话栏

从上到下排列：

- “健康助手”产品名及“健康知识与情绪支持”小字。
- 宽按钮“＋ 新建对话”。
- “历史对话”标题及会话列表。
- 用户名和“退出登录”入口，固定在侧栏底部。

会话项展示自动生成的标题和简短时间，选中项有浅青绿背景及明显文字状态；长标题单行省略，鼠标悬停时可查看完整标题。删除按钮在键盘聚焦和手机触摸场景下也必须可访问，不能只有悬停时才可操作。

没有历史记录时显示“还没有对话，从一个问题开始吧”。历史加载时显示占位列表，失败时显示“历史对话加载失败”和“重新加载”；不能把请求失败伪装成无记录。列表底部提供“加载更多”。

不放搜索、置顶、重命名、分享等未定义功能。生成中列表仍可阅读，但新建、切换和删除操作禁用并说明需先停止回答。

删除确认框文案：标题“删除这段对话？”，正文“删除后，这段对话及消息将无法恢复。”按钮为“取消”“删除”。默认焦点放在取消按钮。

### 5.3 空白聊天状态

中心显示：

> 你好，想了解什么健康知识？
>
> 可以聊聊睡眠习惯、压力调节或日常健康知识。

下面放四个示例问题卡片：

| 示例 | 填入输入框的内容 |
| --- | --- |
| 改善睡眠习惯 | 最近总在睡前刷手机，怎样逐步改善睡眠习惯？ |
| 缓解学习压力 | 备考时容易紧张，有哪些简单的放松方法？ |
| 了解情绪变化 | 怎样区分偶尔心情低落和需要寻求帮助的情况？ |
| 与他人沟通 | 心情不好时，我该怎样向家人表达自己的感受？ |

点击示例仅填入并聚焦输入框，由用户确认发送，不直接调用模型。空白状态不创建数据库会话。

### 5.4 消息阅读区

- 用户消息右对齐，使用浅青绿色气泡；助手回答左对齐，使用白色或浅底阅读块，宽度适合中文阅读。
- 每条消息标明“你”或“健康助手”，无需真实头像。助手标签下方展示 Markdown 正文。
- 初始等待显示“正在思考…”；收到第一段文字后移除此占位，开始增量展示。
- 回答结束后显示“复制”按钮；已停止或失败的部分回答也可复制。
- 仅当前会话最后一条失败或停止的助手消息显示“重新生成”；如果有旧片段，点击时确认“重新生成将替换这次未完成的回答”，按钮为“取消”“重新生成”。
- 已成功完成的回答首版不提供重新生成、编辑问题或多个答案分支。
- 用户停留在底部附近时随新内容滚动；用户向上查看历史时暂停自动滚动，出现“回到最新”按钮。
- 加载更早消息时保留原有可视位置。空回答不能留下一个无说明的空白气泡。
- 非本人或不存在的会话显示“会话不存在或无法访问”以及“开始新对话”按钮，不显示其他账号内容。

### 5.5 底部输入区

多行输入框提示：“输入你的问题，例如：怎样调整睡前习惯？”默认约 2 行高，随输入增长，达到约 160px 后在框内滚动。

输入框下方左侧显示字符数量，例如 `128 / 2000`（已输入字符数/最大字符数）；桌面显示“Enter 发送，Shift + Enter 换行”。右侧为发送按钮，图标必须有文字或可访问名称。

| 状态 | 输入框 | 按钮与提示 |
| --- | --- | --- |
| 空白 | 可编辑 | 发送禁用 |
| 有合法内容 | 可编辑 | 显示“发送”，可点击 |
| 正在提交，尚未接收 | 保留文本，暂时只读 | 显示“发送中…”，不能重复提交 |
| 后端已接收，等待首段/生成中 | 输入框清空且暂时只读 | 主按钮变为“停止生成” |
| 停止请求处理中 | 暂时只读 | 显示“正在停止…”，待确认后恢复 |
| 回答完成/停止/失败 | 可编辑 | 恢复发送；失败的旧问题在消息区可重试 |
| 超过字符限制 | 可编辑，突出超出数量 | 发送禁用，提示“最多输入 2000 个字符” |
| 词元预算不够 | 保留原内容 | 提示“问题过长，请精简后发送” |

浏览器收到 `meta`（后端接收事件）后才清空草稿并采用返回的消息 ID；不得以模拟定时打字替代真实接口流。快捷键仅在非中文输入法组词状态生效。

输入框下方固定一行小字：“回答由 AI 生成，仅供健康知识参考，不能替代专业诊疗。”正常聊天不反复弹出警告框。

### 5.6 状态提示文案

| 情况 | 文案 | 用户可执行操作 |
| --- | --- | --- |
| 模型请求被拒绝，正在忙 | 模型正在处理其他请求，请稍后重试。 | 保留问题，稍后发送 |
| 模型不可连接 | 模型服务暂时不可用，请稍后重试。 | 重试；不显示服务器路径或堆栈 |
| 等待超时 | 等待回答超时，请稍后重试。 | 重新生成 |
| 流式回答失败 | 回答中断，请重试。 | 查看部分回答，重新生成 |
| 主动停止 | 已停止生成。 | 查看部分回答、重新生成或继续提问 |
| 刷新导致中断 | 上次回答已中断，可重新生成。 | 重新生成 |
| 达到生成长度上限 | 回答达到长度上限，可继续提问。 | 输入“请继续”或新问题 |
| 更早上下文被省略 | 本次回答参考了最近的对话。 | 必要时在下一条问题中补充信息 |
| 复制成功 | 已复制 | 短暂提示后消失 |
| 复制失败 | 复制失败，请选中文本手动复制。 | 手动选择文本 |
| 登录失效 | 登录已过期，请重新登录。 | 跳转登录，不自动重复发送问题 |

错误需要出现在对应消息或操作附近，不能仅闪现一个很快消失的提示。收到无法识别的错误时显示一般中文文案，并保留请求 ID 供排查，不直接展示模型服务原始错误。

## 6. 手机与平板布局

- 顶部栏左侧为菜单按钮，中间为“健康助手”或截断后的会话标题；新建入口放在侧栏中，避免顶栏堆满按钮。
- 点击菜单打开左侧抽屉，含桌面端相同的会话列表和退出入口；点击遮罩或关闭按钮收起。
- 选择会话后抽屉自动收起；生成时仍遵守禁用切换的规则。
- 示例问题卡片在手机上单列或两列排布，以文字不拥挤为准。
- 用户气泡与助手回答保留内边距；长链接、代码块内部换行或横向滚动，不让整个页面横向溢出。
- 输入框随软键盘抬起，发送按钮可触达；手机回车换行，通过按钮发送。
- 桌面和手机使用同一会话状态，不因窗口尺寸变化重置聊天记录或重新发起请求。

## 7. 建议组件划分

以下名称为开发建议，括号是中文含义，不要求建立额外页面。

| 组件 | 职责 |
| --- | --- |
| `AuthLayout`（认证布局） | 登录注册共享品牌、卡片和底部提示 |
| `LoginForm`（登录表单） | 字段、校验、提交状态 |
| `RegisterForm`（注册表单） | 注册字段与错误展示 |
| `ChatLayout`（聊天布局） | 桌面栏位、移动抽屉和内容区域 |
| `ConversationList`（会话列表） | 历史、选择、删除、分页 |
| `ChatWelcome`（聊天欢迎区域） | 空状态与示例问题 |
| `MessageList`（消息列表） | 消息顺序、分页和滚动行为 |
| `MessageItem`（单条消息） | Markdown、复制、状态、重新生成 |
| `ChatComposer`（聊天输入区） | 字数、输入法、发送和停止 |
| `ConfirmDialog`（确认弹窗） | 删除与替换未完成回答确认 |

认证状态统一管理，生成状态绑定会话和助手消息 ID；不要仅凭一个全局“正在加载”变量判断所有页面状态。切换账号时清空缓存，避免上个账号内容残留。

## 8. 页面验收与交付

开发 agent 应提交真实截图和简短检查记录，至少覆盖：

1. 桌面登录、注册、聊天空状态、已有多轮聊天。
2. 正在回答、停止后、生成失败及可重试状态。
3. 手机聊天页与展开的会话抽屉。
4. 320px、390px、768px、1440px 视口下无页面级横向溢出，主要按钮可操作。
5. 键盘操作与中文输入法确认不会误发；刷新指定会话路由能正常恢复。
6. 用真实模型接口完成一轮和多轮聊天，说明是否实际验证停止行为、历史保存和账号隔离。

截图中使用演示账号和非真实个人健康信息。交付说明应列出已实现功能、实际验证结果、模型服务依赖及尚未完成项；不可用静态截图证明动态功能已经完成。
